# 엘렝코스 6단계 논술학습 MVP — 구현 현황

「엘렝코스 6단계 논술학습 MVP — 개발자용 종합 기술 설계 가이드」를 이 저장소에 어떻게 반영했는지 정리한 문서입니다.

> **중요**: 지금 들어 있는 문제 패키지 `BASIC-Q1`은 **엔진 동작 확인용 샘플**입니다.
> 제시문 (가)(나)(다)는 새로 쓴 글이고 (다)의 인물은 가상 인물입니다. 채점표 항목 배점과 단계 카드 문구도 임시값입니다.
> 설계 문건 12종(01·02~08·09-1·09-2·10·11)과 HTML 시제품 2종을 받으면 **데이터 파일만 바꾸면 되도록** 만들었습니다.

## 2. 가이드 장별 대응

| 장 | 구현 |
|---|---|
| 3 턴 파이프라인 | 학생 발화 → 엔진이 단계·하위 목표 확인 → 헌장+단계 카드+허용분+이전 산출물+대화로 입력 조립(`LLMTutor`) → 발화+구조화 판단 → 응답 검사(최대 1회 재생성, 실패 시 안전 발화) → 저장, 학생에게는 발화만 |
| 4 단계 엔진 | 상태 `locked→in_progress→summarizing→judging→completed`, `flagged`(교사 진행 허용). 하위 목표 met/partial/not_yet/skipped, 하위 목표 8턴마다 사다리 +1, 단계 40턴 초과 시 flagged. 이어하기 요약. 앞 단계는 다시 열지 않음(6단계 ‘중단 후 보충’만 예외) |
| 4 단계 정리 | 칸마다 **학생 발화에서만** 후보를 채우고, 최종 값의 출처(학생 발화 id / 직접 작성)를 저장 → 판정자 → 미충족이면 튜터가 그 칸을 다시 물음 |
| 5 AI 튜터 | 출력 JSON(utterance, subgoal_id, subgoal_status, issue_type, student_quote, passage_refs, scaffold_level, support_level_so_far, thinking_change, handoff_note, flag_teacher). 사다리 0~5 ↔ 지원 수준 4종, **한 턴에 한 칸**(두 번째 정답 요구만 5칸까지). 답 요구·모르겠어요·과제 이탈·배경지식·반대(타당하면 철회, AI 오류로 기록)·위험 신호(즉시 중단, 안내문, 교사 알림) 처리. 지원 수준은 학생에게 보이지 않음 |
| 5-7 응답 검사기 | 물음표 2개 이상, 250자 초과, 예시답안·기준 해석·완료 기준 문장과의 겹침(3-gram) → 불합격. 경량 모델 검사(키가 있을 때) |
| 6 문제 패키지 | 공개 범위 view: `view_student`(시험지만), `view_tutor`(이 단계 허용분, **예시답안·채점표 제외**), `view_grader`. 로더가 하위 목표 누락·채점표 참조·배점 합을 검사 |
| 7 원고지 | textarea 입력 + 원고지 미리보기(20칸×20행×2장, 700칸 안내선, 장별 누적), 줄 끝 부호 매달기, 숫자·소문자 두 자, 줄 첫머리 공백 제거(**화면 배치에만**). 공식 글자 수 = 입력 본문(공백·부호 포함, 줄바꿈 제외). IME 조합 중 갱신 보류, 800칸 초과 저장 거부, 700자 초과는 경고만. `spellcheck=false`. 10초 자동 저장. 버전 ①독립 초고 ②자기검증 ③선행 수정본(무수정이면 ①을 가리킴) ④제출본(영구 고정, 인계 정보 저장). 붙여넣기(30자↑ 교사 알림)·도움 요청(내용 질문은 6-1로 저장)·중단 후 보충·접근성 기록. 자기검증 5항목은 ‘유지’면 구절+이유 필수 |
| 8 6-1 | 제출 즉시 채점(결과 비공개) → 자기진단 → 영역 점수·항목 이유(강점 먼저) → 첨삭 상위 3개 표시, 나머지 ‘더 보기’ → 항목별 스레드(뜻 확인→근거→기능→수정·유지 판단→검증), 같은 판단점 두 번 막히면 설명 지원, 세 번이면 unresolved → 수용/부분 수용/비수용(+이유, 타당하면 철회) → 새 원고지에 최종본(제출본 미리 채움, AI 문장 삽입 없음) → 같은 채점표로 재평가, 전후 비교·diff → 다음 점검 질문 → 예시답안은 이 뒤에만 선택 열람 |
| 8-2 채점 계산 | AI는 수준·근거만, 점수는 코드: 배점×수준÷4, 영역 합, 총점(소수 둘째 자리), 700자 초과 → E2=0, 보류(null)는 0점과 구분해 ‘잠정’. 인용 위치 검증·보정(못 찾으면 재채점), **2회 독립 채점**, 2 이상 차이 → 3회째 + 교사 검토 권장 |
| 8-4 첨삭 표시 | number·rubric_refs·anchor(버전 id+문자 범위+인용)·mark_type·nature·margin_note·status·student_decision·revision_link(학생 수정안 → 문자 diff → 신뢰도 낮으면 ‘대응 구절 없음’)·support_steps |
| 8-6·8-7 | 최종본에 AI 예시(사다리 5 부분 예시·예시답안)와 거의 같은 문장 → 교사 알림. 최종본 점수는 항상 ‘첨삭 후’ 라벨 |
| 8-8 이의 제기 | 항목 재채점 → 달라지면 새 평가(이전 결과·이유 보존, 현재 적용 버전 표시), 같으면 교사 검토 대기열 |
| 9 돌아보기 | 유형 1만. 개인 성찰은 학습 DB(임시저장·제출·건너뜀, 최초 응답과 수정 구분), 의견은 별도 저장소. **익명이면 계정·회차 id·정확한 시각 미저장(날짜만)**, 제출 전엔 서버에 보내지 않음. A1 변경 시 A2 초기화, A3은 실제 제출본·최종본·사고 변화에서 선택 |
| 10 학생 화면 | 처음 안내(최초 1회 필수), 학습 홈(현재 단계·이어하기·다음 점검 목표·‘달라진 점’), 0단계(시험지 원문 먼저), 1~5단계(왼쪽 제시문·오른쪽 문답·진행 막대·하단 이전 산출물 서랍), 단계 정리 폼, 6단계, 6-1 좌우 첨삭(모바일 탭 대신 세로 배치), 돌아보기, 나의 기록(JSON 내려받기, 내부 판단 제외) |
| 11 교사 대시보드 | 학급 현황(이름순, 현재 단계·턴 수·지원 수준 분포·알림), 검토 대기열(접수/검토 중/조치 완료/보류+이유), 학생 상세(타임라인 전체 문답·판단·검사 결과·모델/지침 버전, 사고 변화+메모, 답안 버전 diff·작성 시간·붙여넣기, 평가 항목 수정(이유 필수, 이전 값 보존, 새 행), 돌아보기 ↔ 실제 지원 수준), 의견 집계(5명 미만이면 원문만), 지도교사 안내(예시 장면·오류 유형표·채점표) |
| 12 권한 | 학생 화면으로 가는 응답에 시험지·본인 기록 외 자료를 싣지 않음(테스트로 확인). 교사는 학생 문답·답안 본문 수정 불가. 열람·수정은 감사 로그 |
