# 요구사항 정의서 반영 현황 (1차 구현)

기준 문서: 「논술학습 기초다지기 요구사항 정의서」(초안, 2026-10-27, 요구사항 578건)
이 문서는 무엇을 어디에 구현했는지, 4장 '확인 필요 사항'을 어떻게 정했는지, 아직 남은 것이 무엇인지 정리한다.

## 1. 구조 — 공통 실행 틀 (Z-047~Z-050)

다섯 영역을 각각의 프로그램으로 만들지 않았다. **엔진 하나 + 영역별 콘텐츠 묶음(YAML)** 구조다.

| 계층 | 위치 | 역할 |
|---|---|---|
| 콘텐츠 | `content/v1/` | 제시문(승인 발췌문 계층), 학습 주제 L1~L5, 보충 경로 S1~S5(23개), 복습 항목 38개 |
| 모델·로더 | `src/learning/content.py` | 묶음 스키마, 버전별 로딩, 참조 무결성 검사 |
| 정책 엔진 | `src/learning/engine.py` | 교수 순서, 지원 단계, 반복 상한, 생략, 독립 확인, 보충 호출·이력, 진입 판정 호출 |
| 판정 | `src/learning/entry.py` | 진입 준비 판정표 (테스트로 고정) |
| 수준·지원 | `src/learning/levels.py` | 공통 기록 스키마 (수준 3/2/1/0/미확인, 지원 7종) |
| 분석기 | `src/learning/analyzer.py` | AI는 답변 분석만 (충족 기준·대표 오류·불확실 여부). 다음 행동은 엔진이 결정 |
| 기록 | `src/learning/state.py` | 최초 답·수정 답·지원 이력·기준별 판정·검토 요청·이벤트 |
| 화면 | `views/` | 학생: 홈·학습하기·진단 결과·선택 복습 / 교사: 학습 기록·자료 관리 |

AI의 역할 제한(Z-049): AI는 `Diagnosis`(met, primary_error, concept_gap, uncertain)만 돌려준다. 질문 문구는 콘텐츠에 승인된 **첫 대응 질문·설명·시범**만 쓴다. 진입 판정, 반복 상한, 답안 공개, 보충과 복귀는 엔진 정책이 처리한다.

## 2. 주요 요구사항 반영

| 요구사항 | 구현 |
|---|---|
| Z-014 교수 순서 | `Engine.submit`: 시도 → 진단 → 방향 질문 → 설명 → 시범 → 기록 후 이동 |
| Z-015·L1-005 최초 수행 전 답 비공개 | 최초 시도 전 도움은 어휘·과제 안내·“잘 모르겠어요”만. 정답 문구는 학생 화면 어디에도 없음 |
| Z-017·Z-027 지원 수준 | `SUPPORT_CEILING`: 방향 질문·과제 안내·구조 지원 → 최대 2, 설명·시범 → 최대 1, 어휘·확인 질문 → 영향 없음 |
| Z-018·L1-020 같은 판단점 2회 | `MAX_DIRECTIONS_PER_POINT = 2`, 이후 설명 → 시범으로 전환. 개념 미이해면 즉시 전환 |
| Z-008·L1-010·L1-012 충분한 답의 생략 | `skip_if_met`: 앞 단계에서 같은 기준을 충족하면 단계 생략 (예: 일반화, 숨은 전제, 일반-사례) |
| Z-009·L5-004 산출물 이어 쓰기 | `carry_from`(다른 묶음은 `L4:step`), `prefill_from` |
| Z-010·Z-017·Z-030 불확실 | 확인 질문 1회 → 그래도 불확실하면 미확인 + 교사 검토 요청 |
| Z-020·L3-002 중단·재개 | “저장하고 나가기” → 답·위치 보존, 같은 세션으로 재개. 학생 활동 시간과 AI 대기 시간 분리 집계 |
| Z-023·Z-024 세 층위 기록 | 단계 수준(과제 수행) / 기준 ①~⑤(진입 준비)로 분리. 숙달 판정은 하지 않음 |
| Z-025·L1-025 최소 기록 | 자료 버전, 최초 답, 제공한 도움, 수정 답, 기준별 판단과 근거 단계, 다음 확인(보충 경로) |
| Z-026·Z-028·S2-057~060 진입 판정 | `judge_entry` + `tests/test_entry.py` (S2-061 시나리오 포함) |
| Z-029 총점 금지 | 총점 계산 없음. 기존 100점 채점 흐름 제거 |
| Z-031·S3-001 관계·추론 프로필 | L3 기준은 `evidence_for` 없음 → 기준 ①~⑤에 일괄 반영하지 않고 단계별 수준으로만 기록 |
| Z-033·S1-011·S2-011 보충 1~2개·한 회기 | `supplement_options`: 초점 기준 최대 2개, 경로당 1회. 재시작 차단 |
| Z-034·S1-119·S1-135 재확인 | 보충의 직접 연습은 기준 미갱신(재학습 후 수행), 다른 제시문 재확인만 갱신. 방향 질문 1회 후 성공 → 2 |
| S1-143 미확인 종료 | 재확인 미확인이면 기존 수준 유지 + 교사 검토(“보충 후 수행 미확인”) |
| Z-036 반복 대신 검토 | 필요한 보충이 이미 끝났으면 교사 검토 요청 생성 |
| Z-037·Z-038 결과 화면·이의 | 진단 결과: 할 수 있는 것 / 도움이 필요한 부분 / 이유 / 다음 학습. 근거 응답 열람 + 재확인 요청 |
| Z-044·S2-066 학생 화면 | 내부 기준 번호·수준 코드는 교사 화면에만. 학생에게는 평이한 문장 |

## 3. 4장 ‘확인 필요 사항’에 대한 결정

| No | 결정 |
|---|---|
| 1 원본 사본 | 구현 영향 없음 |
| 2 P 제2편 위계 | P-021~P-027 중 기초 과정 관련(버전 고정, 원문·생성 구별)만 반영. 심층·압축·실전 모드는 본격 6단계와 함께 구현 |
| 3 시간 기준 | 묶음별 `time_target`에 문서 값을 그대로 두고 **표시만** 한다. 시간으로 통과·탈락시키지 않음(Z-020). 시범 운영 후 하나로 정리 |
| 4 판정 명칭 | Z-028 네 가지로 통일: 진입 가능 / 조건부 진입 / 집중 보충 후 재확인 / 판정 보류—확인 필요 |
| 5·6·7 편집 잔재 | 구현 영향 없음 (원본 문서 정리 대상) |
| 8 참조 대조 | “공통 11.x” = Z 11항으로 보고 판정표를 `entry.py`에 구현 |
| 9 본격 6단계 | 미작성이므로 결과 화면에서 “준비 중”으로 안내. 선택 복습 카탈로그와 추천 기록 구조만 선구현 |
| 10 자료 교체 시 연결 | 복습 연결은 제시문이 아니라 **판단 기준·오류 유형의 `skill`/`review_item`**에 걸어 두어, 제시문을 바꿔도 유지되게 함 |
| 11 반론 시범 시점 | 학생이 반론을 한 번 이상 시도했거나 “잘 모르겠어요”를 누른 뒤에만, 다른 주장에 대한 시범으로만 제공 |
| 12 자기검토 트리거 | 자기검토 단계는 AI 개입 없이 완료. 제출 단계에서만 중요한 공백 하나를 질문. 문제가 없으면 질문 없이 완료 |
| 13 기록 스키마 | `levels.py` 하나로 통일 (수준 5종 + 지원 7종) |
| 14 판정표 | `entry.py` + 테스트 16건으로 고정 |
| 15 범위 | 실제 발췌문 검수는 별도 단계 (아래 5절) |

## 4. 데모 모드

- 테스트 로그인(`test`/`testpoc`)은 Supabase 없이 브라우저 세션에만 기록한다.
- AI 키가 없으면 `DemoAnalyzer`가 콘텐츠의 `signals`(키워드 단서)로 판정한다. **시연용이며 실제 평가에 쓰면 안 된다.** 타당한 다른 표현을 놓칠 수 있다(P-013).
- AI 키를 넣으면 `LLMAnalyzer`가 같은 판단 기준으로 분석한다.
