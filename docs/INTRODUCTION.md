## 1. 무엇이 다른가요

일반적인 첨삭 프로그램은 글을 받아 **점수를 매기고 고친 문장을 보여 줍니다**.
논술랩 기초 다지기는 그렇게 하지 않습니다.

| 일반 첨삭 | 논술랩 기초 다지기 |
|---|---|
| 총점 100점으로 평가 | **총점 없음.** 다섯 기준을 각각 기록하고 판정표로 안내 |
| 모범 답안·수정 문장 제공 | **답을 먼저 알려 주지 않음.** 학생이 직접 쓰고 고침 |
| 도움을 받아도 같은 점수 | **도움의 종류를 기록.** 도움을 받아 해낸 것은 혼자 해낸 것과 구분 |
| 틀리면 같은 질문 반복 | 같은 지점의 질문은 **2번까지**, 그다음은 설명 → 다른 글로 시범 |
| 못하면 다시 처음부터 | **필요한 부분만** 10~15분 보충하고, 해낸 것은 그대로 보존 |

## 2. 학습 흐름

```mermaid
flowchart LR
    subgraph basics["기초 다지기 · 각 1회"]
        L1[① 읽고 한 문장으로 잡기] --> L2[② 주장과 이유 연결하기]
        L2 --> L3[③ 두 글 비교와 추론 점검<br/>1차·2차 활동]
        L3 --> L4[④ 내 주장을 세우고 시험하기]
        L4 --> L5[⑤ 짧게 쓰고 고치기<br/>400자 이내]
    end
    L5 --> J{진입 준비 판정<br/>기준 ①~⑤}
    J -- 진입 가능 / 조건부 진입 --> F[본격 6단계<br/>준비 중]
    J -- 집중 보충 후 재확인 --> S[집중 보충<br/>경로당 1회 · 10~15분]
    S --> R[다른 글로 재확인] --> J
    J -- 판정 보류 --> T[교사 확인]
```

### 한 활동 안에서는 이렇게 진행돼요

```mermaid
flowchart LR
    A[스스로 시도] --> B{AI가 답 분석}
    B -- 충분함 --> OK[해냈어요 ✓<br/>다음 활동]
    B -- 부족함 --> D1[방향 질문 1]
    D1 --> A2[다시 시도] --> B2{분석}
    B2 -- 부족함 --> D2[방향 질문 2] --> A3[다시 시도] --> B3{분석}
    B3 -- 부족함 --> E[개념 설명] --> A4[다시 시도] --> B4{분석}
    B4 -- 부족함 --> M[다른 글로 시범] --> A5[다시 시도] --> B5{분석}
    B5 -- 부족함 --> REC[기록해 두고 다음 활동<br/>필요하면 보충에서 다시]
```

받은 도움에 따라 기록되는 수준이 달라집니다.

| 수준 | 언제 |
|---|---|
| **3 독립 수행** | 도움 없이 해냄 (어휘 뜻만 물어본 경우 포함) |
| **2 최소 지원 후 수행** | 답을 알려 주지 않는 방향 질문·과제 안내 뒤에 해냄 |
| **1 집중 지원 후 수행** | 설명이나 시범을 본 뒤에 해냄 |
| **0 미형성** | 설명과 시범 뒤에도 아직 어려움 |
| **미확인** | 판단할 근거가 부족함 — 틀렸다는 뜻이 아님 |

## 3. 학생 화면

### 3-1. 수업 화면 — 제시문과 과제를 나란히

왼쪽에는 제시문, 오른쪽에는 현재 과제와 튜터와의 대화가 있습니다.
제시문에는 **제목·저자·출처를 표시하지 않고** `(가)`, `(나)` 같은 기호만 씁니다. 학생이 배경지식이 아니라 본문으로 읽게 하기 위해서입니다.

![수업 화면](screenshots/desktop_02_lesson.png)

학생이 소재만 말하면, 답을 알려 주는 대신 **생각할 방향을 묻는 질문**이 나옵니다.
쓴 답은 입력창에 그대로 남아 있어서 고쳐 쓰기만 하면 됩니다.

![방향 질문](screenshots/desktop_03_direction.png)

### 3-2. 막힐 때 — 질문 → 설명 → 다른 글로 시범

같은 지점에서 계속 막히면 질문을 무한히 반복하지 않습니다. 질문 두 번 → 개념 설명 → **다른 연습문으로 시범** 순서로 도움이 커집니다.
시범은 일부러 다른 글을 씁니다. 지금 과제의 답을 보여 주지 않기 위해서입니다.

![지원 단계](screenshots/B_01_escalation.png)

### 3-3. 판단 과제와 학습용 해석 문장

제3주제에서는 해석 문장이 원문에 비추어 **타당한지, 조건부로 타당한지, 뒷받침되지 않는지** 판단합니다.
AI가 만든 해석 문장은 “학습용 해석 문장 · 원문 아님”으로 원문과 구별해 보여 줍니다.

![판단 과제](screenshots/desktop_04_judge.png)

### 3-4. 짧은 글쓰기 — 400자, 쓰는 동안은 혼자

제5주제에서는 제4주제에서 세운 주장·근거·반론·대응을 **다시 입력하지 않고 불러와** 400자 이내의 글을 씁니다.
글자 수는 공백을 포함해 실시간으로 표시하고, 초고를 쓰는 동안에는 AI가 내용에 끼어들지 않습니다. 초고·자기검토본·최종본은 따로 보관됩니다.

![초고 쓰기](screenshots/desktop_05_draft.png)

### 3-5. 진단 결과 — 점수 대신 “할 수 있는 것”과 “다음 학습”

다섯 주제를 마치면 진입 준비 결과가 나옵니다. 내부 기준 번호나 점수 대신 평이한 문장으로 안내합니다.

| 혼자 해낸 학생 | 중심 생각 잡기가 어려웠던 학생 |
|---|---|
| ![진입 가능](screenshots/desktop_07_result.png) | ![보충 안내](screenshots/B_02_result_supplement.png) |

보충이 필요하면 **가장 직접적인 부분 하나**만 짧게 다룹니다. 원래 제시문으로 직접 연습한 뒤 **새 글로 다시 확인**하고, 같은 규칙으로 판정을 다시 적용합니다.

| 집중 보충 | 보충 후 다시 판정 |
|---|---|
| ![보충](screenshots/B_03_supplement.png) | ![재판정](screenshots/B_04_result_after.png) |

결과에 동의하지 않으면 근거가 된 자기 답을 보고 재확인을 요청할 수 있습니다.

### 3-6. 선택 복습

1-1부터 5-7까지 38개의 짧은 복습입니다. 어려움이 보였던 항목에는 ✨ 추천 표시가 붙지만, **하지 않아도 학습은 이어집니다**.
열면 설명과 다른 예의 시범을 먼저 보여 주고, 원래 과제의 답은 공개하지 않습니다.

## 4. 교사·운영자 화면

### 4-1. 학습 기록 — 판정의 근거까지

학생 화면에는 보이지 않는 내부 기록을 교사가 확인합니다.

- 기준 ①~⑤의 수준과 **그 수준을 정한 학생 답**, 그때 받은 도움, 콘텐츠 버전
- 활동별 **처음 답과 고친 답**, 어떤 도움 뒤에 고쳤는지, AI 분석 내용
- 검토 요청: 판정이 불확실한 경우, 학생 이의, 보충 후에도 확인되지 않은 경우
- 교사가 판정을 고치면 **사유를 남기고** 같은 규칙으로 다시 판정

![학습 기록](screenshots/desktop_08_records.png)

### 4-2. 자료 관리 — 버전과 즉시 사용 중지

제시문의 내부 출처, 사용 위치, 승인 상태를 확인합니다. 사실 오류나 부적합한 자료는 사유를 적고 **즉시 사용 중지**할 수 있습니다.
진행 중인 학습은 시작할 때의 콘텐츠 버전을 그대로 유지합니다.

![자료 관리](screenshots/desktop_11_content_admin.png)

## 5. 어떻게 만들었나요

```mermaid
flowchart TB
    subgraph screens["화면"]
        V1[학생: 홈 · 학습하기 · 진단 결과 · 선택 복습]
        V2[교사: 학습 기록 · 자료 관리]
    end
    subgraph core["공통 실행 틀"]
        E[교수 정책 엔진<br/>질문 횟수 · 설명·시범 전환 · 생략 · 보충 · 복귀]
        J[진입 판정표]
        A[답변 분석기<br/>AI는 분석만]
    end
    C[(콘텐츠 묶음 YAML<br/>제시문 · 판단 기준 · 오류별 첫 질문 · 설명 · 시범)]
    D[(학습 기록<br/>Supabase / 데모)]
    V1 & V2 --> E
    E --> A
    E --> J
    C --> E
    E <--> D
```

- **영역마다 따로 만들지 않았습니다.** 엔진 하나에 다섯 학습 주제와 보충 경로 23개를 콘텐츠로 연결합니다. 제시문을 바꿔도 교수 원칙은 그대로 유지됩니다.
- **AI의 역할은 분석으로 제한했습니다.** 학생 답이 어떤 기준을 충족했고 어떤 어려움이 보이는지만 판단합니다. 무엇을 묻고 언제 설명하고 어떻게 판정할지는 교사가 승인한 콘텐츠와 시스템 규칙이 정합니다.
- **기술:** Streamlit · Supabase(PostgreSQL, 인증, 행 단위 권한) · Claude / OpenAI · Pretendard 글꼴
